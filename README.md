# Rule Replay

**A fluent plan isn't a valid plan.** Meta Llama proposes a bounded action plan for a fictional game. An independent, developer-authored simulator replays every step against the declared rules. A failed step produces an exact counterexample that feeds one bounded repair attempt. Nothing is ever labeled verified unless it actually passed the replay.

Built for the **Meta Global AI Developer Hackathon** (Cerebral Valley, November 2026).

## Live product

- App: https://rule-replay.farfazlearning.workers.dev
- Demo video (captioned walkthrough, real outcomes in order): https://rule-replay.farfazlearning.workers.dev/rule-replay-demo.mp4
- API: `POST /api/plan` with `{"scenario_id":"robot"}`, `GET /api/scenarios`, `GET /api/counterexample` (labeled developer-authored negative test, no AI).

## Stack

- **Model**: `@cf/meta/llama-3.3-70b-instruct-fp8-fast` via Cloudflare Workers AI (OpenAI chat shape handled).
- **Verifier**: deterministic simulator in `worker.js` (`simulate()`). The model never sees the simulator's code and cannot mark its own plan verified. The checker is developer-authored, not generated by the model it checks.
- **Frontend**: single static page in `public/index.html`, served as a Worker static asset.
- **Deploy**: `npx wrangler deploy` with `wrangler.toml` (no secrets in this repo; the AI binding is account-level).

## Honest results

In the observed live runs, Llama 3.3 70B's proposed plans **failed verification**: the model repeatedly tried to `collect` on a square with no star (step 4), and the bounded repair attempt failed too, at the same step. The product reports `not_verified` with both counterexamples, exactly as designed. The demo video shows this real outcome; no simulated success is substituted anywhere. The interesting engineering result is that fluent model plans need independent checking, and that a single counterexample-grounded repair was not enough for this fixture.

## Scope and limits

- Only fixed fictional inputs are accepted. No free-text rules, no external actions, no learner data.
- `verified_against_fixture` means only that the trace conforms to this fixed fictional simulator. It is not real-world truth, teaching approval, or a safety guarantee.
